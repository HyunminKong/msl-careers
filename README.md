# MSL Careers

Media System Lab (MSL)의 Research 부문 채용 콘셉트 홈페이지입니다.
파란색과 흰색을 중심으로 한 대기업 채용 사이트 분위기의 독립 디자인이며,
삼성의 로고·사진·원본 코드를 사용하지 않았습니다.

## 파일 구성

```text
index.html   # HTML, CSS, JavaScript, 벡터 그래픽을 모두 포함한 홈페이지
.nojekyll    # GitHub Pages에서 정적 파일을 그대로 게시하기 위한 설정
README.md    # 실행, 배포, 수정 안내
```

별도 패키지 설치, 빌드, API 키 또는 서버 프로그램이 필요하지 않습니다.
이미지·아이콘·스타일·스크립트는 모두 index.html 안에 들어 있습니다.
외부 웹폰트나 라이브러리를 불러오지 않으며, 운영체제에 설치된 글꼴을 사용합니다.
따라서 기기마다 글꼴 모양은 조금 다를 수 있습니다.

하단에 채용 홍보용 콘셉트 페이지임을 표시했습니다. 실제 모집 여부와 세부 조건은 담당자 확인이 필요합니다.

## 1. 내 컴퓨터에서 보기

압축을 풀고 `index.html`을 브라우저에서 열면 됩니다.
로컬 파일에서는 브라우저 설정에 따라 클립보드·저장 기능이 제한될 수 있습니다.
공고 링크 공유는 GitHub Pages에 게시한 다음 사용하세요.

## 2. GitHub Pages에 올리기

1. GitHub에서 새 **Public** 저장소를 만듭니다. 예: `msl-careers`.
2. **Add file → Upload files**를 선택하고, 압축을 푼 파일을 올린 뒤 커밋합니다.
   `index.html`이 저장소의 최상위에 있어야 합니다.
   `msl-careers/index.html`처럼 상위 폴더까지 통째로 올리지 마세요.
3. 저장소의 **Settings → Pages**로 이동합니다.
4. **Build and deployment → Source**에서 **Deploy from a branch**를 선택합니다.
5. **Branch**는 `main`, 폴더는 `/(root)`로 선택한 뒤 **Save**를 누릅니다.
6. 배포가 완료되면 같은 화면의 **Visit site**에서 홈페이지를 확인합니다.

일반 프로젝트 저장소의 주소 예시:

```text
https://YOUR_GITHUB_ID.github.io/msl-careers/
```

별도의 저장소 경로 없이 계정 대표 주소를 쓰려면 저장소 이름을 `YOUR_GITHUB_ID.github.io`로 만드세요.
이 경우 사이트 주소는 다음과 같습니다.

```text
https://YOUR_GITHUB_ID.github.io/
```

계정 대표 사이트를 이미 사용 중이라면 기존 파일을 덮어쓰지 말고,
`msl-careers`처럼 별도 프로젝트 저장소를 만드는 편이 안전합니다.
게시 반영에는 시간이 걸릴 수 있으며, 문제가 있으면 저장소의 **Actions** 탭에서 배포 결과를 확인하세요.

GitHub 공식 안내:
- https://docs.github.com/en/pages/getting-started-with-github-pages/creating-a-github-pages-site
- https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site
- https://docs.github.com/en/pages/quickstart

## 3. 문구와 색상 수정

`index.html`을 VS Code 등의 텍스트 편집기로 열고 수정할 문구를 검색하세요.

주요 구역:
- `id="about"`: 메인 문구와 일러스트레이션
- `id="recruit"`: 채용 공고 카드
- `id="life"`: 복지 카드
- `id="qualifications"`: 필수·우대 조건
- `id="apply"`: 담당자 안내

맨 위 CSS의 `:root`에서 주요 색상을 조정할 수 있습니다.

```css
--blue: #1748e5;       /* 메인 파란색 */
--blue-dark: #1039bd;  /* 버튼 호버 */
--navy: #101e46;       /* 문의 영역 배경 */
```

페이지 제목이나 공고 문구를 바꾸면 `<title>`, `description`, `og:title`,
`og:description`도 함께 수정하는 것이 좋습니다.

## 4. 실제 이메일 연결하기 (선택)

현재 문의 버튼은 담당자 선택과 문의 문구 복사 기능을 엽니다.
메시지는 자동 전송되지 않으며, 복사 후 알고 있는 담당자 연락처로 직접 보내는 방식입니다.

실제 이메일 주소를 받았다면 HTML 하단의 아래 설정에서 빈 문자열만 채우세요.
유효한 이메일을 입력한 담당자에 대해서만 **이메일로 보내기** 버튼이 표시됩니다.

```js
const CONTACT_EMAILS = {
  '오규태': '',
  '공현민': ''
};
```

이메일 버튼은 기기의 기본 메일 앱을 열 뿐 자동 발송하지 않습니다.
문의 창 안에서 작성한 내용을 메일 제목·본문에 반영합니다.
공개 연락처로 사용해도 되는 주소인지 담당자에게 먼저 확인하세요.

## 기능 및 데이터 처리

- 데스크톱·태블릿·모바일 반응형 레이아웃
- 모바일 접이식 메뉴와 하단 지원 문의 버튼
- 관심 공고 표시: 브라우저 로컬 저장소에 저장 여부만 기록
- 공고 공유: 기기 공유 기능 또는 링크 복사
- 문의 창: 담당자 선택, 문구 편집·복사, 닫기·다시 열기 시 현재 페이지 내 초안 유지
- FAQ 펼치기·접기
- 공고 인쇄용 스타일
- 키보드 탐색, 모달 포커스 복귀, 동작 줄이기 설정 지원

이 페이지 자체에는 분석 도구, 지원서 업로드, 로그인, 개인정보 접수 서버가 없습니다.
문의 초안은 현재 페이지 메모리에만 유지되며 새로고침하면 사라집니다.
실제 온라인 지원 접수가 필요하면 별도의 접수 서비스나 서버 연결이 필요합니다.

게시 후 해당 주소에서 링크 공유와 브라우저 간 동작을 최종 확인하세요.
